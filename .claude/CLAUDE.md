# alexsay: Claude handover

You are picking up a hardware + software project with a context window that never saw how it started. Read this first, then `docs/` as needed. History is in [`handover.md`](handover.md).

## What we're building

- A free-standing cylinder speaker (≈150 mm Ø × 210 mm, set by the driver's square frame; measure it on arrival) that replaces an Amazon Echo Dot.
- Wake word **"Alexsay"** opens a full-duplex OpenAI voice session (`gpt-live-1`, with `gpt-realtime` as a fallback backend). The user can interrupt the assistant mid-sentence (barge-in).
- Home Assistant runs on the same Pi; the assistant controls the home through it via function calls.
- Voice only. Music playback was dropped on 10 Oct 2026 (it may come back cheaply if the Flex 48 kHz firmware turns out full-band; see docs/device-design.md).

- Develops on **Ubuntu Linux**. Has the LetterBox project's tools (TS21 soldering iron, PPK2) on hand.
- London, UK suppliers (The Pi Hut, RS, Farnell, Amazon UK).

## Server and app facts

- Live since 10 Oct 2026: Worker `alexsay-app` (app.alexsay.com, D1 `alexsay`), Worker `alexsay-www` (www.alexsay.com and alexsay.com). Deploy token `alexsay-deploy` and the e2e account passwords are in `.env` only. `just e2e` passes against production.

- Browser assistant: the Worker brokers only the SDP exchange (`POST /v1/live/sessions` with `transport: {type: "webrtc", sdp}`), audio travels WebRTC browser to OpenAI, JSON events over the `oai-events` data channel. Function calls arrive as `response.event` envelopes wrapping `response.output_item.done`; the browser answers with `response.item.create` (`function_call_output`) + `response.create`.
- A speaker's UUID is its identity and its secret: whoever adds it in the app owns it; the heartbeat then returns the owner's OpenAI key and settings to the speaker. Unclaimed call-home rows are capped at 200.
- Provider credentials are AES-GCM sealed in D1 under `SECRETS_KEY` (Worker secret, also in `.env` for `just dev`). Lightwave refresh tokens rotate on every use and are re-sealed.
- Passwords are salted PBKDF2-SHA256 (100k) hashed on the server; `scripts/hash-password.mjs` makes the same format for `just add-user`.
- Both `alexsay.com` and `www.alexsay.com` serve the website (no redirect; canonical is www).
- Telephony (11 Oct 2026): Twilio is a third connection (account SID + auth token sealed; settings: `from_number`, `my_number`, `whatsapp_from`, `sip_domain`, `country_code`). Saving with a number sets that number's Voice/SMS/status webhooks to `/v1/twilio/{voice,messages,status}` on this app; every webhook is checked against the owner's auth token (X-Twilio-Signature). The assistant's phone tools run server-side through `api/src/telephony.ts`: `place_call` rings `my_number` and bridges with `<Dial>`, or reads a message out with `<Say>`; conferences use the Participants API with a friendly name (host leg `EndConferenceOnExit`); texts and WhatsApp go through `Messages.json`. Incoming calls ring every claimed speaker as `sip:{deviceId}@{sip_domain}` plus `my_number` at once; the speaker will register with a SIP client (baresip) using its UUID as the SIP username (credential list still manual). The Twilio MCP server (`mcp.twilio.com/docs`) is docs-only, so there is nothing to wire into the assistant.
- Phone calls from the app (11 Oct 2026): a tool call carries `client.voice = "browser"` when the Assistant page has registered as Twilio Client `alexsay-app` (Voice SDK, token from `/api/twilio/voice-token`, API key created on first use and sealed with the Twilio secret). Calls open on the page by default; the mobile rings only when the user asks (`via: "mobile"`); a page without its line gets an error instead of a surprise call. Every call is a conference built in stages by Twilio status callbacks: `place_call` creates only the host leg (browser `client:alexsay-app?conference=...` or the mobile, `EndConferenceOnExit`, guests kept as JSON in `calls.brief`); the host answering dials the guests and seats the assistant right behind them (unique index `calls_one_assistant`); the trigger is the page's own `POST /api/twilio/conferences/:name/answered` (sent when it accepts its leg), Twilio's `answered` status callback, or the conference's `participant-join` event at `/v1/twilio/conference` (`ConferenceStatusCallback` on every participant; `conference-end` marks all legs completed), whichever comes first (on 11 Oct Twilio stopped delivering participant status callbacks for a while) and dials `sip:{project_id}@sip.api.openai.com;transport=tls?X-Alexsay-Conference=...`. The page accepts its leg only once its own GPT-Live assistant has been quiet for 0.8 s. OpenAI's `realtime.call.incoming` webhook at `/v1/openai/webhook` is verified Standard-Webhooks style with that user's secret, accepted with the briefing (who is on, who answered, the task, the live conversation's last 30 turns, memories) and the whole tool registry minus `end_conversation`; then the `CallAgent` Durable Object (one per call id) holds the realtime socket for the call (opened with an https fetch plus `Upgrade: websocket`: workerd refuses `wss://` URLs, which silently left the first calls without tools; failures now land in the server log) and runs the function calls through the registry with a `ToolContext` (`tool_context.ts`), so "Alexsay, hang up", "add Dad" and `press_digits` (DTMF for menus: the guest leg is redirected to `<Play digits>` and `<Dial><Conference>` back) work from inside the call. Tools take a `ToolContext {env, user, origin, voice}`, not a Hono context; connection helpers take any `Scope {env}`. The page mutes its GPT-Live session while a call is connected; End conversation, Hang up and `pagehide` (sendBeacon) all end the host leg, which ends the conference. The Twilio SDK is built with `window.AudioContext` hidden and `disableAudioContextSounds`, shares the GPT-Live microphone track (with autoGainControl applied), and incoming calls to the number also ring `<Client>alexsay-app</Client>`. Volume of the far side and of the assistant's SIP voice cannot be raised through Twilio or OpenAI. Call reports (11 Oct 2026): the assistant's SIP leg is accepted with input transcription, and `CallAgent` stores every finished transcript line in `call_turns` (speaker `assistant` or `line`, the mixed audio of everyone else). The end of a call is recorded once in `call_reports` by whichever signal comes first (`end_call` by user or assistant, Twilio `conference-end` with `ended_by` derived from who left first via `calls.left_at`). The page hands the report back the instant its own leg drops: it polls `GET /api/twilio/conferences/:name/report` until `ready` (assistant leg closed, or 4 s after the end), then pushes it into its GPT-Live session with `response.item.create` of a `message` item (`input_text`) plus `response.create` (probed live on 11 Oct: GPT-Live accepts it and speaks the reply when audio is flowing), and records it as a tool turn so the digest sees it. `call_report` reads it back later. The speaker daemon should do the same from its own leg-drop event. Test calls (11 Oct 2026): Settings "AI call test" (`users.ai_call_test`) adds `call_test` and `add_test_agent`: a scripted OpenAI leg (`X-Alexsay-Agent=<calls.id>` SIP header, brief = `{role, scenario, voice}`, voice name or random by male/female) is dialled as the guest and accepted with `agentBrief` and only the agent-only `leave_call` tool (hidden from users). Turn-taking on calls (11 Oct 2026): both SIP legs are accepted with `server_vad` (semantic detection added 3 to 5 s per turn); the person's side (or the test agent) `holds` (550 ms silence, `interrupt_response: false`) and the assistant `yields` (850 ms, interruptible), so two voices starting together resolve instead of both cancelling; `PHONE_ETIQUETTE` in `telephony.ts` says the same in words. GPT-Live's speech layer can answer "yes, call them" without delegating, so no tool runs and it narrates a call that does not exist (seen 11 Oct 16:02); the instructions now forbid claiming a call without a tool result, and `call_status` reads every leg's live status from Twilio (`GET /Calls/{sid}`) so the page assistant answers from facts.
- Call path hardening (13 Oct 2026): the speaker's self-call is answered with the stream at once and `hostAnswered` runs in `waitUntil` (the host's `participant-join` retries it); `calls.claimDialling` makes dialling the guests atomic (several triggers race); guests and the assistant are dialled in parallel and one failure does not stop the rest; the assistant's seat row carries its briefing from the INSERT (OpenAI's webhook can arrive before Twilio's REST reply); `calls.setStatus` never leaves a final status and reports whether it changed; the assistant's `CallAgent` is named `assistant:<conference>` and takes `/notify` (a system item: "X answered", or "X did not answer: busy" plus `response.create`); the briefing forbids claiming ringing or an answer before being told. Every `logFor` is awaited (floating promises die with the response and lost webhook log lines). The speaker's line dropping mid-call hangs the call up (13 Oct 2026; a stopped daemon had left one up for 3.5 minutes): `LineBridge` closes Twilio's stream and runs `endCall` through the REST API, on the device socket's close or, for a socket that dies silently, from an alarm when the speaker has sent nothing at all for 12 s (`DEVICE_SILENCE_MS`): during a call the speaker pings every 5 s, muted or not, on top of its 50 audio frames a second (25 s pings otherwise). A quiet user is not silence; only a dead connection is.
- Server log (11 Oct 2026): `server_log` keeps per-user lines (tool calls, call stages, webhooks, provider failures, call agent events) via `logFor()` in `api/src/log.ts`, purged after 7 days by the nightly cron. The `read_log` tool (tail/head, 5 lines by default, 100 max) exists only when the user ticked "AI log access" in Settings (`users.ai_log_access`, `PATCH /api/session/settings`).
- Locale and time zone (11 Oct 2026): `users.locale` (BCP 47, default `en-GB`) and `users.timezone` (IANA, default `Europe/London`), set in Settings "Where you are" (`PATCH /api/session/settings`, validated with `Intl`). `localeInstructions()` in `api/src/locale.ts` opens every session's context (page, call briefing, test agent): the user's current date and clock in their zone, language, currency with a formatted sample, date and time samples. The heartbeat returns `account: {locale, timezone}` for the speaker (the Rust `HeartbeatReply` does not read it yet).
- Contacts live in D1 (`contacts`, unique per user and E.164 number, indexed on `search_name` and favourites; `messages` and `calls` keep the history). The app imports them with the Contact Picker API (Android Chrome, iOS Safari) or a `.vcf` file; numbers are normalised with the user's `country_code` (default +44).

## The speaker binary (12 Oct 2026)

- Releases (12 Oct 2026, first v0.1.1), like streamx: `just release patch` (scripts/release-tag.sh: bump `device/Cargo.toml`, git-cliff CHANGELOG.md with cliff.toml, tag, push, `gh release create` with notes and a Downloads table), or the cut-release workflow. `.github/workflows/release.yml` builds on native runners and uploads with `gh release upload`: `alexsay-x86_64-linux-musl` and `alexsay-aarch64-linux-musl` (bare static binaries via the flake, aarch64 with the `flex` feature, built on ubuntu-24.04-arm), `alexsay-aarch64-macos` and `alexsay-x86_64-macos` (bare, built on macos-14, Intel run under Rosetta), `alexsay-x86_64-windows.zip` and `alexsay-aarch64-windows.zip` (static CRT, windows-2025 and windows-11-arm). `scripts/release-check.sh` runs every binary on its own architecture before upload (version, target, identity, config, wake engine over a generated WAV; no server calls). The checksums job writes `SHA256SUMS` and `SHA256SUMS.sig` (Ed25519, `ALEXSAY_RELEASE_KEY` secret; public key in `device/core/src/update.rs`). The updater maps its target triple to these names (`core::update::asset_name`) and takes bare binaries. macOS signing secrets (`MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`, `APP_STORE_CONNECT_KEY`, `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`) are not set on this repo yet, so macOS builds are ad-hoc signed; GitHub secrets cannot be copied from streamx, they must come from the .p12 and .p8 files on the Mac.
- Nix builds take the git index: `git add` new files before `nix build` or they are missing. The static ALSA comes from `pkgsStatic.alsa-lib` (`lib.getDev` for `alsa.pc`); `PKG_CONFIG_ALL_STATIC` and `+crt-static` make the link static; a `file` check in `postInstall` refuses a dynamic result.
- Layout: `~/.local/alexsay/config.toml` (TOML, every key optional, `alexsay config init` writes the commented example; `Config::set` for `alexsay config set a.b v`) and `data/` with `identity` (0600), `state.json`, `logs/` (daily files, `log.keep_days`), `models/`, `recordings/`, `cache/`. `--home` or `ALEXSAY_HOME` moves it. Secrets never touch disk: the heartbeat hands the owner's OpenAI key over TLS and it stays in memory.
- Server side for the binary (`api/src/routes/device_api.ts`, guarded by `requireClaimedDevice`): `GET /v1/device/session` returns `{api_key, session}` built by `assistant_api.ts sessionFor()`, the exact `sessionConfig` the web page uses (instructions with locale and memories, every tool); `POST /v1/device/tools/call` runs the registry as the owner with `voice: "mobile"` (calls ring the mobile; the speaker has no phone line yet); `/v1/device/conversations` start, `/:id/turns`, `/:id/end` record and digest like the app. The daemon adds `audio.format {audio/pcm, 16000}` to the session and opens `wss://api.openai.com/v1/live/sessions` itself.
- Runtime (`device/daemon/src/runtime.rs`): startup chime; heartbeat task (poll_s, claim state into `state.json`); update task (`update.check_hours`, announces by voice through OpenAI speech `gpt-4o-mini-tts`, verifies, `self_replace`, re-execs); listen loop keeps a preroll ring (`session.preroll_s`), feeds the wake word (rustpotter, `wake.sensitivity`, `wake.refractory_s`), on detection plays the ready tick and runs `converse()`: fetch the session, open GPT-Live, flush the preroll, stream 100 ms chunks, play deltas, run tools through the server (`end_conversation` handled locally), record transcripts, close by the session rules, end tone. Barge-in: two loud chunks (`BARGE_IN_RMS`) clear the playback queue. Errors play the error buzz; "OpenAI not connected" is said at most once a minute.
- Session rules (`core/src/session.rs`, config `[session]`): `idle_timeout_s` (no speech either way), `after_reply_s` (quiet after the assistant finished, shorter), `max_minutes` hard cap, `end_on_farewell` (user farewell phrases plus a short assistant sign-off, ported from the web app), the `end_conversation` tool closes after the reply.
- Wake word (13 Oct 2026): two engines behind `core::wake_engine::WakeEngine`, picked by `wake.engine`: `livekit` (default) or `rustpotter` (kept compiled in, to switch back if LiveKit proves worse or too costly). `daemon::runtime::wake_model` loads the engine's model for every command (`wake.livekit_model` / `wake.model`: `builtin` or a path); before 13 Oct `alexsay setup` checked the built-in model whatever the config said.
  - rustpotter: `device/models/alexsay.rpw` is the owner's model (trained 12 Oct 17:59, from their 40 takes, now in `device/testdata/takes`). Heard as live (`wake_engine::as_heard`: 2.5 s of 0.16% RMS room noise before, 1.5 s after) it catches 20/20 "Alexsay" and fires on 20/20 near-misses: the "wakes on any word". Padding with digital silence (the old `wake test --file`) hid that (4/20). `wake_engine` pins the numbers in a test. Its detection is rustpotter's own falling edge (non-eager, half a window under the threshold after 3 frames above); the refractory skips the audio entirely. `core/testdata/tone.rpw` is a fixed toy model for that timing test (training is random).
  - LiveKit (`core/src/wake_livekit.rs`): their frozen mel and embedding models (`device/models/livekit/`, Apache-2.0) and our classifier `device/models/alexsay.onnx`, run on tract-onnx, not the `livekit-wakeword` crate: its `predict()` recomputes 2 s from scratch (189 ms a call, 236% of a core at 80 ms hops). Streaming: every 80 ms the mel of the last 2 s (the mel model's floor follows the loudest sound in its input, so streaming short chunks does not match their batch features), one new embedding (3.3 ms), the classifier on the last 16; about 4.5% of one laptop core. Scores make the same decisions as LiveKit's batch inference on every hop (test). `core::trigger` turns scores into detections: above 0.6 starts a word, below 0.4 ends it and fires, then a debounce (`refractory_s`); `thresholds_for(sensitivity)`.
  - tract needs `half` >= 2.4, rustpotter's candle 0.2 needed 2.3.1 (Cargo allows one `half` 2.x): `device/vendor/candle-core` is candle-core 0.2.2 with its f16/bf16 random init drawn as f32 (`PATCHED.md`); the flake keeps it real in crane's dependency build. tract grew the static binary from 13 to 32 MB.
  - Training (`just wake-setup [small]`, `just wake-train [small]`, `scripts/wake-train.sh`): LiveKit's toolkit (`livekit-wakeword==0.2.3` from PyPI, in a uv venv in `~/.cache/alexsay/wake`, about 18 GB with ACAV100M features) on `device/wake/alexsay.yaml`: targets "alexsay", "aleksay" (espeak-ng: ɐlˈɛkseɪ, the same as "Alexei", so never a negative), negatives led by "alexa say". The full run copies the ONNX into `device/models/alexsay.onnx`; both runs end with `alexsay wake eval` on the owner's takes. `just wake-eval` compares the engines (caught, false fires, CPU). The global git config rewrites GitHub to SSH, so nothing in the pipeline fetches with git.
  - The rustpotter tools stay: `alexsay wake record` / `wake train` (sets `wake.engine = rustpotter`) / `wake test` (any engine; `--scores`). Older notes: the first shipped rustpotter model came from 169 OpenAI `gpt-4o-mini-tts` takes; rustpotter 3.0.2 needed `half` 2.3.1 until the vendored patch.
- Audio (`daemon/src/audio.rs`): cpal; device chosen by name substring or "auto" (default device; `flex` prefers XVF3800/ReSpeaker); capture at the device rate, channel count and sample format (f32, i16, i32, u16). Both cpal callbacks are real-time: no locks, no allocation, no logging. The input callback only converts and pushes into a lock-free SPSC ring (`ringbuf` `HeapRb`); the resampling thread drains it (`pcm::pick_channel`, rubato `FastFixedIn` to 16 kHz, AEC3) and hands 16 kHz chunks on a bounded channel (dropped and counted in the debug log, never delayed). Playback is a 16 kHz ring the output callback pops and upsamples sample by sample; `clear` sets a mark the callback skips to; the played samples go to the echo canceller through another ring (`Player::take_echo_reference`). On a call, the debug log's `line audio per second` line shows the loudest microphone level sent. On a Linux desktop the static binary speaks to ALSA hardware directly (no PipeWire or Pulse plugins in a static build); the Nix dev shell cannot load the system's PipeWire plugin either, so on this machine use `[audio] input = "HDA Intel"` (hardware devices open fine). A dedicated USB microphone and speaker is the intended setup.
- Service: `alexsay service install` writes a systemd unit (system when root, else user with a linger hint), a launchd agent on macOS, a logon scheduled task on Windows.
- Tests: `cargo test --workspace` (core 35, daemon units), `just e2e-device` (`device/daemon/tests/e2e.rs`, `ALEXSAY_E2E=1`, logs in as the e2e user, claims the binary's id, runs `alexsay smoke --json`, removes the device), and the human checklist in `docs/device-tests.md`.
- Install: `website/public/install.sh` and `install.ps1` (served at alexsay.com with `_headers` content types) download the latest asset and `SHA256SUMS`, verify, install to `~/.local/bin` (or `/usr/local/bin` as root; `%LOCALAPPDATA%\alexsay\bin` on Windows).

- Speaker phone line (12 Oct 2026): `LineBridge` Durable Object per device (`api/src/line_bridge.ts`) holds the speaker's WebSocket (`GET /v1/device/line`, claimed devices only, `/line/status`) and Twilio's media stream (`GET /v1/twilio/stream/:token`). A call on a speaker: `openConference(host: "speaker")` checks the line is up, inserts a `bridges` row (token, device, conference), and makes the user's number call itself (`createCall` with `conferenceHostTwiml`: `<Dial><Conference endConferenceOnExit>`), which is the host leg (`calls.phone = "speaker"`); the voice webhook sees From == To, consumes the pending bridge, runs `hostAnswered` (guests, assistant seat) and answers `<Connect><Stream>` to the bridge token; the DO relays 8 kHz mu-law frames both ways (speaker messages `audio`, `hangup`, `mute`, `ping`; to the speaker `call.start`, `audio`, `call.end`). Two Twilio legs per speaker call. Tool calls from a device get `voice: "speaker"` when its line is up, else `"mobile"`; `callHost()` opens calls where the user talks from (`via: here | mobile`), mobile only on request, same on the page and the speaker; `without_assistant` on the result says why the assistant stays off. The browser keeps the Twilio JS SDK path untouched; the provider split (`providers/twilio.ts`, `telephony.ts`, `app/src/lib/phone_line.ts`) is where another call provider would plug in.
- Local servers (12 Oct 2026): `serverOrigin(c)` is `PUBLIC_URL` or the request origin; `isPublicOrigin()` is false for localhost, `.local`, private ranges. Without a public origin: the assistant is not seated on calls (`without_assistant` reason), speaker lines refuse (`no_public_server`), the Twilio number's routing is left alone on save (`local: true` + note) and `numbers/repair` answers 412; browser calls still work (the page reports answered; `call_status` reads Twilio). A tunnel plus `PUBLIC_URL` restores everything.
- Daemon call mode: `line.rs` keeps the line socket with reconnects (`LineSender::send_audio` halves to 8 kHz and mu-law encodes; `LineSignal` decodes the other way); `control.rs` serves `data/control.sock` (TCP port file on Windows) for `alexsay call status|mute|unmute|hangup`, the future hardware button; `CallState` (on_call, muted, conference) drives `Runtime::route_to_call` (microphone to the line only). A call starting closes the open GPT-Live session (muted, GPT-Live held its unfinished reply and spoke it after the call, 12 Oct 2026); on `call.end` the END tone plays, `hand_back` polls the report and a fresh conversation opens with it as the first item (`Opening::Report`). The mute button sends GPT-Live's input mute.
- Live playback (13 Oct 2026, `core/src/playout.rs`): GPT-Live and call audio arrive at real-time pace, silence included; past 200 ms queued, silent blocks are dropped (speech never), so a burst cannot become lasting delay (it was 3 to 5 s). The daemon has no barge-in of its own: GPT-Live handles being talked over. Nothing on the async runtime blocks waiting for playback; the microphone is read throughout. Updates wait while a conversation or call is on.

- GPT-Live over WebSocket, as observed 12 Oct 2026: `session.output_audio.delta` carries only `type` and `delta` (no timing fields) and arrives for the whole session, silence included; `session.usage.updated` has fractional `usage.seconds` and a `context_window`. Every event field except `type` is `#[serde(default)]` in `core/src/live.rs`, so lean or newer events still parse (an unparsed event falls into `Other` and is ignored; the debug log names its fields). "The assistant is talking" means reply audio above `AUDIBLE_RMS`, not a non-empty queue.
- Software echo cancellation (12 Oct 2026, `device/daemon/src/echo.rs`): WebRTC AEC3 through the pure-Rust `sonora` crate. The player copies every block it plays (silence included, after volume) to the canceller as the reference; the canceller runs on the capture resampling thread at 16 kHz in 10 ms blocks, before GPT-Live or a phone call hear the microphone. The wake word hears the raw microphone (13 Oct 2026: its model is trained on raw takes and the speaker is quiet while it listens); the canceller still runs on every block to stay converged (`duplex::echo_cancelled`). `[audio] echo = "auto"` is software everywhere except the Flex build (hardware); software counts as echo-cancelled, so barge-in is on. Measured on the ALC256 laptop with the microphone at 60 %: replies heard at ~1.3 % against ~80 % without. At 100 % capture gain the echo clips and AEC3 barely helps (36 to 56 %), so the capture level matters. `RUST_LOG=alexsay=debug` logs the canceller's own reduction every 5 s.
- Echo (`[audio] echo`, `core/src/duplex.rs`): without hardware echo cancelling (laptops, plain USB microphones) the speaker is half duplex: the assistant hears silence while it talks and nothing local cuts its playback; with the Flex (`auto` on the flex build) talking over it interrupts. Speech and barge-in are judged against a rolling noise floor (20th percentile of ~4 s), not fixed levels. GPT-Live has no echo cancelling of its own for a WebSocket client; the browser path gets it from getUserMedia.
- Testing the running speaker: `alexsay call inject <wav>` feeds a recording into its microphone path (the running process holds the sound card, so `aplay` cannot reach it); after each reply the log says how loud the microphone heard it.

## The self-hosted server (12 Oct 2026)

- `server/` is `alexsay-server`, its own Cargo workspace. The Rust launcher embeds `server/build/bundle.tar.zst` (workerd, the Worker bundled by `wrangler deploy --dry-run --config server/wrangler.selfhost.jsonc`, `app/dist`), made by `scripts/server-bundle.sh <arch>-<os>`. Without a bundle it still compiles (empty, with a warning). It unpacks to `~/.local/alexsay-server/data/runtime/<sha8>`, writes `config.capnp`, generates `data/secrets.toml` (0600: `SECRETS_KEY`, admin token), supervises workerd, runs `/scheduled` daily, never calls home or self-updates (Andreas: updates are manual only).
- `api/src/selfhost/`: `entry.ts` (env shim, `Admin` WorkerEntrypoint on a loopback socket with Bearer token: `/health`, `/scheduled`, `/users`), `d1.ts` (D1 on a SQLite-backed Durable Object `D1Store`, migrations from `migrations.generated.ts`, regenerated by `scripts/selfhost-migrations.mjs`; a Vitest test fails if it drifts), `assets.ts` (disk service as the ASSETS binding with `_headers` and SPA fallback). workerd forbids sharing I/O objects across requests: create DO stubs per call.
- Provider URLs are workerd bindings `fromEnvironment` (`ALEXSAY_OPENAI_BASE_URL` etc.), set from `config.toml` keys (`openai_base_url`, `lightwave_*`, `twilio_base_url`); `registration = false` sets `REGISTRATION=closed` (403 `registration_closed`). The session cookie is `Secure` only over HTTPS or `x-forwarded-proto: https`. Self-hosted has no `CF-Connecting-IP`, so sign-in rate limits share one address.
- The heartbeat and `/v1/device/session` carry `base_url` (the server's `OPENAI_BASE_URL`); the speaker derives its GPT-Live socket and speech URL from it (`core::live::live_url`), defaulting to OpenAI.
- Linux: workerd exists only as glibc; the bundle carries glibc's `ld-linux`, `libc.so.6`, `libm.so.6` from the flake's nixpkgs and the launcher runs workerd through that loader, so the static musl launcher (rust-lld, `server/.cargo/config.toml`) runs on Alpine. workerd gets `PR_SET_PDEATHSIG`. Windows server is x86_64 only (no workerd for Windows on Arm).
- Releases are created as drafts by `scripts/release-tag.sh`; the checksums job publishes them (`--draft=false --latest`) once every binary is attached and signed, so `install.sh` and speakers never see a release without files.
- CI e2e: `server-e2e` (built server, throwaway accounts) and `prod-e2e` (app.alexsay.com, credentials from the `production` environment's secrets, main only) run the same Playwright suite and speaker e2e. Generated passwords and speaker ids are masked; Playwright traces are never uploaded.
- Blog (12 Oct 2026): `website/src/content/posts.ts` holds post meta with a `published` time; bodies are components in `website/src/posts/`. Posts are scheduled: before its time a post 404s (the Worker), the prerendered `/blog` drops its `[data-publish]` card (HTMLRewriter), and `/sitemap.xml` and `/blog/feed.xml` (RSS, generated by the Worker) leave it out, so a post goes live with no deploy. Assets use `html_handling: drop-trailing-slash` so URLs match the canonical tags. Each page has JSON-LD (Organization, WebSite and SoftwareApplication on home, Blog, BlogPosting).
- README hero: `just readme-screenshot` captures the live site's landscape hero into `docs/media/hero-{day,night}.jpg`. The home page ends with a Development section: `website/src/components/DevTerminal.tsx` (xterm.js, lazy-loaded) plays `website/src/content/terminal.ts`, real install, train and run output.
- Gates: `just e2e-server` (Playwright minus the website spec, plus the speaker e2e, throwaway accounts) runs in CI; `scripts/server-release-check.sh` runs each release binary on its own runner (and on Alpine for Linux). Release assets: `alexsay-server-<arch>-linux-musl`, `-<arch>-macos`, `-x86_64-windows.zip`; the release notes have Speaker and Server tables.

## Key facts to keep straight

- The **XVF3800 does both capture and playback**, so the AEC reference is the exact signal sent to the speaker. Never route speech output through another sound card: that breaks AEC and brings back the combine-sink/clock-drift problem we designed away.
- Flex firmware is **geometry-specific**: only `*-cir.bin` images for this board. Flashing a `-lin` image is explicitly unsupported by Seeed.
- Flex USB firmware options (Seeed repo, whole-repo download only):
  - `respeaker_flex_ua-io16-6ch-cir.bin`: 16 kHz, 6 ch (0 conference, 1 ASR, 2 to 5 raw mics). Bring-up and wake-word data capture.
  - `respeaker_flex_ua-io48-cir.bin`: 48 kHz, 2 ch. Production candidate if playback proves full-band.
  - `respeaker_flex_ua-io16-cir.bin`: 16 kHz, 2 ch.
- 16 kHz playback cuts everything above ~8 kHz: speech stays clear (wideband, like HD Voice), music sounds muffled.
- Flex amp: rated 10 W at 4 Ω on its 12 V terminal; on USB 5 V expect ~3 W (estimate, to measure). We run it from USB only.
- Visaton R 10 S 4 Ω: fs 160 Hz, Qts 1.45, Vas 1.9 L, Xmax ±0.5 mm, 92.6 dB/1 W, 100 Hz to 13 kHz, 93 mm cut-out. High Qts: any small sealed box peaks 6 to 8 dB around 220 to 270 Hz, so **high-pass ~150 Hz and a peaking cut at fc are mandatory** (applied in the daemon before playback, so AEC still sees the true output).
- Pi 5 on the 27 W PSU allows 1.6 A total on USB. Budget: XVF3800 + amp peak < 1 A.
- GPT-Live takes PCM16 mono at **16 kHz** or 24 kHz, fixed at `session.start` for both directions. With the io16 firmware the daemon runs at 16 kHz end to end, no resampling. (`gpt-realtime` is 24 kHz only and needs a resampler.)
- GPT-Live tools: Responses delegation to a backend text model; custom functions arrive as `response.output_item.done` inside `response.event`, the daemon runs them and returns `function_call_output` + `response.create`.

## Gotchas already discovered

- The Flex with XIAO ships with **I2S firmware**: it does not appear as a sound card. Safe Mode = hold **Boot** while powering on, then `sudo dfu-util -l` shows `2886:001a`. I2S firmware only accepts I2C DFU, so Safe Mode is the only USB route.
- Flash through the **XMOS USB-C port next to the RST button**, not the XIAO's USB-C.
- Download Seeed's firmware by cloning the whole repo; GitHub "save as" corrupts the `.bin`.
- The Flex has **no mute button and no LED ring** (one green power LED). Mic mute and status feedback are software: earcons through the speaker.
- The XIAO ESP32-S3 stays powered after the reflash and runs whatever it shipped with. Check its current draw and RF; flash a deep-sleep sketch if it matters.
- The **JST PH 2-pin "male header" cables** ordered from The Pi Hut mate with *female plug* cables (LiPo style), so they likely do not fit the board's speaker header. The female version is sold out. The Flex has a **solder pad for a hard-wired speaker**: use it.
- R 10 S terminals are tabs: **5.2 mm (+)** and 2.8 mm (−). No standard push-on for 5.2 mm: solder, heat-shrink.
- Never drive the R 10 S hard while unbaffled on the bench: no box means no air load and the cone over-excurses at low frequencies.
- The SanDisk High Endurance card came from a marketplace seller (Electrolyx UK): verify capacity with `f3write`/`f3read` before trusting it.
- Raspberry Pi SSD (all capacities), the SSD Kit and the Pimoroni NVMe Base were **out of stock or discontinued in the UK on 10 Oct 2026**. NAND prices made other NVMe drives £60 to £90+. Start on the SD card.
- Wake word is **"Alexsay"** (changed from "Alex" on 10 Oct 2026). "Alexa, say..." sounds almost the same, so it is the most important negative, with "Alexa", "Alex", "Alex says", "Alexei" and TV speech.

## Code rules

- Same as LetterBox. Everything runs inside the Nix flake: `nix develop` (or direnv), then `just <recipe>`. Add tools to `flake.nix`, never ask for global installs.
- `just test` must pass before a task is done: `cargo fmt --check`, `cargo clippy -D warnings` (pedantic), `cargo test`, Biome, `tsc`, Vitest (api in workerd with local D1), app and website builds. `just e2e` runs against the deployed site with the `test-admin` / `test-user` accounts from `.env`; `just deploy` ends with it.
- TypeScript: strict, no `any`, validate input with zod, parameterised D1 queries only.
- Clean, self-documenting code: descriptive names over comments. Comment only the non-obvious why, one line. No commented-out code.
- No em-dashes anywhere (code, comments, docs).
- Rust: no `unwrap`/`expect`/`panic` outside tests. Protocol, state machine and DSP logic live in a host-tested `core` crate with no I/O; ALSA, WebSocket and HTTP glue lives in `daemon`.
- Secrets (`CLOUDFLARE_API_TOKEN`, `SECRETS_KEY`, `ALEXSAY_RELEASE_KEY`, e2e passwords) only in `.env` and GitHub Actions secrets; the speaker keeps none on disk. Never in the repo. Commits go out under Andreas's own account with no Claude co-author line.
- Every behaviour change ships with a test.
- Docs stay lean: bullets and tables, no introductions. Update `docs/` and this file when facts change.
